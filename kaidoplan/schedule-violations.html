Check schedule violations before committing a date

Run KaidoPlan’s violation report and distinguish a deadline conflict from its effects on upstream tasks.

Download KaidoPlan for macOS Download the demo plan

Run the report on the current plan

Open the violations view in KaidoPlan or run the CLI below. The public demo produces a finish-constraint conflict for Publish release plus negative-slack entries on its upstream chain. A report with several entries does not necessarily mean there are several independent causes.

kaidoplan violations --file release-demo.kaido --lang en
kaidoplan schedule path --file release-demo.kaido --lang en

Fix the cause in a copy

Read the failing task, constraint and predecessors together. Check whether the target date is fixed and whether the tasks can legitimately overlap. Change only assumptions you can justify, recompute and rerun the report. Keep the original file so you can compare changes or roll back.

Know what the check can tell you

A passing report means the model found no reported violation under the inputs you supplied. It cannot verify that estimates are realistic, that someone is available or that a release will pass review. Check those assumptions with owners and update the model when circumstances change.
